# Data Model: SQL 分頁一次執行多段 SQL

這個功能不會在資料庫裡存任何東西。下面的 entity 都只存在於一次請求裡，用來描述前後端之間傳的資料。

## 執行批次

使用者按一次執行送出的整段 SQL。

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `config` | 物件 | 連線資訊，跟其他 API 相同，見 README |
| `database` | 字串，選填 | MySQL 是資料庫名稱，執行前先 `USE`。PostgreSQL 是 schema，執行前先 `SET search_path TO <schema>, public` |
| `sql` | 字串，必填 | 編輯框裡的完整內容，可以有多段 |

驗證規則：

- `sql` 是空字串或沒有帶時，回 400，訊息「請輸入 SQL」。
- 切分後沒有任何可執行的段落時，回 400，訊息「沒有可執行的 SQL」（FR-007）。

一個執行批次對應一條資料庫連線。請求結束時連線一定會關閉，不管成功還是失敗（FR-017）。

## 段落

批次切開後的一個 SQL 語句。

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| 編號 | 整數 | 畫面上從 1 開始。API 的 `failedIndex` 從 0 開始 |
| `sql` | 字串 | 原始文字，包含開頭的註解，不含結尾的分隔符號 |

驗證規則：

- 拿掉 `--`、`#`、`/* */` 註解和空白之後是空的，就不算一個段落，也不算進 `total`（FR-006）。
- MySQL 的 `DELIMITER` 那一行不算段落，也不會送去執行（FR-003）。

## 段落結果

一個段落成功執行後的結果，分成兩種，用 `type` 區分。

查詢結果（`type: "select"`）：

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `sql` | 字串 | 該段的原始文字 |
| `rows` | 物件陣列 | 每一列是 `{欄位名: 值}`，0 筆時是空陣列 |
| `columns` | 字串陣列 | 欄位名稱，順序跟資料庫回傳的一樣 |

寫入結果（`type: "write"`）：

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `sql` | 字串 | 該段的原始文字 |
| `affectedRows` | 整數 | 影響筆數，`USE`、`SET`、DDL 是 0 |
| `insertId` | 整數或 `null` | MySQL 有 auto increment 時是新增的 ID，其他情況是 `null`。PostgreSQL 一律是 `null` |
| `message` | 字串 | 開頭是 `INSERT`、`UPDATE`、`DELETE`、`REPLACE` 時是「執行成功 — 影響 N 筆資料」，其他是「執行成功」（FR-011） |

判斷規則見 research.md R3：看結果有沒有回傳欄位，不看開頭的關鍵字。

## 失敗資訊

批次中途失敗時產生，放在 HTTP 500 的回應裡。

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `error` | 字串 | 多段時是「第 N 段執行失敗：<資料庫錯誤訊息>」，只有一段時就是資料庫的錯誤訊息 |
| `failedIndex` | 整數 | 失敗段落的位置，從 0 開始 |
| `failedSql` | 字串 | 失敗段落的原始文字 |
| `total` | 整數 | 這個批次的總段數 |
| `results` | 段落結果陣列 | 失敗前已經成功的段落，長度等於 `failedIndex` |

還沒執行的段數是 `total - failedIndex - 1`。

## 執行流程

```text
收到請求
  → sql 是空的？ → 400「請輸入 SQL」
  → 開連線，失敗就 500（跟其他 API 一樣）
  → 有 database 就先 USE 或 SET search_path
  → 切分，略過空段落
  → 沒有段落？ → 400「沒有可執行的 SQL」
  → 依序執行每一段
       成功 → 加進 results，繼續下一段
       失敗 → 500，帶失敗資訊，停止
  → 全部成功 → 200 { results }
  → 關閉連線
```
